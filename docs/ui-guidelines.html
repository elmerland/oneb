SEC 001

Color palette

· 5 CRT accents + ink + paper

Five screen-lit accents on a near-white paper ground (#fafaf5) with deep ink black for all structural elements. Each accent has a fixed positional role in the nav strip and the pop-rule divider — they read as a set, not interchangeably. Never combine two accents as foreground/background pairs. Accents always appear on cream or ink.

Selection highlight: background: var(--c-red); color: var(--cream).

SEC 002

Typography

· three IBM Plex faces, one type scale

The site uses three members of the IBM Plex family, each with a distinct job. Never introduce a fourth typeface. The type scale is defined as CSS custom properties derived from --fs-base: 1rem — all sizes scale together if the base changes.

SEC 003

Layout

· one column, fluid gutter

All pages use a single centered column. The page container (.page) caps at --content-max: 760px with a fluid horizontal gutter of clamp(20px, 5vw, 56px). There are no multi-column page layouts — only internal component grids (library books, media) use multi-column grid. Prose and post feeds are strictly single-column.

LAYOUT CONSTANTS --content-max: 760px  ·  --gutter: clamp(20px, 5vw, 56px)  ·  Mobile breakpoint: 720px

Breakpoint: 720px. Below this width the masthead stacks vertically, nav items wrap into a grid, and the wordmark scales down to preserve the ASCII art proportions.

Prose and post body: capped at 74ch inside the already-narrow column — prioritizes readable line length over filling the container.

Images in prose: default to max-width: 70% centered, expanding to max-width: 100% on mobile.

SEC 004

Site chrome

· masthead, nav, rule strip

The chrome is the structural frame rendered on every page. It consists of three stacked elements: the masthead (wordmark plate + bio), the nav strip, and the 5-color rule strip. Everything below the rule strip is page-specific content.

SEC 005

Post feed

· list of posts on the home/archives page

Posts on the feed are simple vertical stacks: date → title → summary excerpt. No left borders, no numbered chips, no background fills. Each post is separated by a 5-segment pop-rule divider. Post titles use IBM Plex Sans (not mono) — one of the most important distinctions from earlier designs.

SEC 006

Prose

· article body rendered inside .prose

Full blog post content renders inside .prose. The body face is IBM Plex Serif; headings inside prose switch to IBM Plex Sans (800, uppercase). All inline code is IBM Plex Mono on an ink background. Block code gets the same ink background plus a red hard-offset shadow. Blockquotes use a 3px red left border.

There is a particular pleasure in noticing a number flip over that means nothing to anyone else. The odometer on the way to work. A photo timestamped one year to the minute from another. Your one-billionth second.

The background

A long time ago I watched a video by Neil deGrasse Tyson about how long one billion seconds is. The calculation is simple: one billion seconds is roughly 31.7 years. The video stayed with me for some reason.

The best software is the kind you stop noticing. You use it, it works, and then you think about something else.

Inline code looks like this: const billion = 1_000_000_000. Block code gets the full treatment:

// seconds since epoch
const age = (Date.now() / 1000) - birthEpoch;
const isBillion = age >= 1_000_000_000;

  • No tracking, no newsletter, no roadmap.

SEC 007

Library page

· books grid, media grid, tags

The library page has two content types: books (shown in a 2-column auto-fill grid with covers) and media items (blog, video, podcast, other — shown as a narrower multi-column grid). Both use the same border and typography system as the rest of the site. Tags are small bordered labels with per-type translucent accent backgrounds.

SEC 008

Interactions

· hover, focus, reduced motion

Three interaction patterns are used across the site. Each applies to a specific context — they are not interchangeable. Animations always respect prefers-reduced-motion: reduce, which collapses all durations to 0.01ms.

hover me — body link
.t-text — UNDERLINE REVEAL Used for all readable body links (post titles on feed, prose links, bio tagline). No color change — only a 1px underline that scales in from left on hover. Preserves reading flow.
ONEB (hover the wordmark)
.t-glitch — CHROMATIC ABERRATION (text) Used only on the wordmark / logo link. On hover: alternating cyan/red text-shadow at ±4–6px, stepping through 2 frames at 320ms. Simulates CRT channel misalignment.

SEC 009

Usage rules

· what to do and what to avoid

Do

  • Use IBM Plex Mono for all UI chrome — nav, dates, labels, badges, the wordmark, and any code.
  • Use IBM Plex Sans for post titles on the feed and headings (h1–h3) inside prose.
  • Use IBM Plex Serif for all prose body text and post summaries on the feed.
  • Use ink black (--plate) for all borders — always 1.5px solid.
  • Keep hard offset shadows pointing down-right: 8px (masthead), 6px (code, images), 4px (nav), 3px (badges).
  • Use the 5 accents in their positional order for nav tiles and pop-rule segments.
  • Limit each element to one accent color. Accents are ink-on-cream emphasis, not field fills.
  • Keep post body and prose inside a 74ch max-width column.
  • Reserve .t-glitch for the wordmark and nav-glitch-box for nav tiles only.
  • Use .t-text (underline reveal) for all readable body links.
  • Always include prefers-reduced-motion support.

Don't

  • Don't introduce a fourth typeface. The three IBM Plex faces cover every typographic need.
  • Don't use rounded corners, soft drop-shadows, or gradients anywhere.
  • Don't pair two accents as 50/50 foreground/background. Accents appear on cream or ink, not on each other.
  • Don't use uppercase on post titles — they're sentence case IBM Plex Sans.
  • Don't apply chromatic glitch to body text or generic links — only the logo and nav tiles get it.
  • Don't color-shift links on hover — the underline reveal is the only signal.
  • Don't use emoji or raster iconography — ASCII glyphs only (●, ·, //, →).
  • Don't add borders or background fills to blockquotes beyond the 3px left border.
  • Don't break the single-column layout for page-level sections; only library grids may use multi-column.
  • Don't hard-code pixel sizes — always use the --fs-* scale tokens.
SEC 010

CSS tokens

· paste into :root · source: src/styles/global.css

All values below are defined in src/styles/global.css inside :root. Do not redefine them in component styles; reference the variables instead. Change --fs-base to rescale the entire type system proportionally.

:root {
  /* Surfaces */
  --bg:     #fafaf5;   /* page background        */
  --plate:  #171a20;   /* ink black               */
  --ink:    #171a20;   /* body text               */
  --cream:  #fafaf5;   /* component fills         */
  --dim:    rgba(23, 26, 32, 0.55);   /* secondary text       */
  --hair:   rgba(23, 26, 32, 0.16);   /* hairline dividers    */

  /* CRT accent palette */
  --c-red:    #ff5d3a;   /* amber flare    — nav-1, plate shadow, hover */
  --c-cyan:   #00c2ff;   /* ice cyan       — nav-2, glitch channel      */
  --c-yellow: #ffd60a;   /* hot yellow     — nav-3                      */
  --c-plum:   #ff2d75;   /* magenta pulse  — nav-4                      */
  --c-green:  #00d97e;   /* phosphor green — nav-5, reading tag         */

  /* Shadows — hard offset, always pointing down-right */
  --shadow:        8px 8px 0 0 var(--c-red);    /* masthead plate */
  --shadow-plate:  4px 4px 0 0 var(--plate);    /* nav strip      */
  --shadow-red-sm: 6px 6px 0 0 var(--c-red);    /* code, images   */

  /* Layout */
  --gutter:      clamp(20px, 5vw, 56px);
  --content-max: 760px;

  /* Type scale (base: 1rem = 16px) */
  --fs-base:    1rem;
  --fs-3xs:     calc(var(--fs-base) *  9 / 14);   /* ~10px — wordmark, tiny labels */
  --fs-2xs:     calc(var(--fs-base) * 10 / 14);   /* ~11px — swatch labels, tags   */
  --fs-xs:      calc(var(--fs-base) * 11 / 14);   /* ~13px — dates, nav (mobile)   */
  --fs-sm:      calc(var(--fs-base) * 12 / 14);   /* ~14px — nav (desktop), footer */
  --fs-md:      calc(var(--fs-base) * 13 / 14);   /* ~15px — code blocks           */
  --fs-lg:      calc(var(--fs-base) * 20 / 14);   /* ~23px — bio name, prose h3    */
  --fs-h2:      clamp(
    calc(var(--fs-base) * 20 / 14),
    calc(3.2vw * 16 / 14),
    calc(var(--fs-base) * 28 / 14)
  );
  --fs-h1:      clamp(
    calc(var(--fs-base) * 26 / 14),
    calc(4.4vw * 16 / 14),
    calc(var(--fs-base) * 36 / 14)
  );
}
